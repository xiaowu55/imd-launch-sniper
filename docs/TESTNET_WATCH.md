# Sepolia 新发行观察与区块延迟实测

这项测试等待启动后才部署的新代币，并用独立测试钱包执行一次真实买入。它与购买旧 Hook #358 的功能验证分开保存，不能相互替代。

## 运行方式

先按照 README 的测试网流程准备独立钱包及免费 Sepolia ETH，然后运行 `npm run testnet:watch -- start`。同一工作目录只有一个固定的观察窗口，不会因重启自动延长或重复购买。`npm run testnet:watch -- status` 读取状态；`npm run testnet -- status-fresh` 仅查询已记录的新币交易。

固定观察 30 分钟，最多一次买入，金额 0.0001 Sepolia ETH，滑点 1%，Gas 最大费用 0.002 Sepolia ETH。主网控制台不参与；钱包不从主网 `.env` 读取。

## 新币判定与选择

1. 读取官方完整分页列表，排除当时所有 Sepolia LIVE ID，保存双 RPC 一致的起始区块与哈希。
2. 本节的旧版 30 分钟 `testnet:watch` 按 API 返回的缓存周期轮询；后续持续模式已改为 2 秒目标周期，见下文。启动时 parked 或尚未上线的记录可以在后来上线时进入候选。
3. 通过正式 API 发射核验模块绑定部署交易、登记事件、合约代码及 v4 池参数。发射区块必须严格大于观察起点，同时不晚于首次发现后读取的链头。
4. 当前一批已核实候选按链上区块、交易索引、日志索引排序。临时无法核验的候选会阻止直接买后面的候选；未知或不兼容协议会记录拒绝原因。
5. 选中前重新读取列表；锁定交易前和广播前再次检查被选记录仍为 LIVE，且没有新增 LIVE 候选改变选择依据。发生变化就停止，不能拿一次失败自动换买第二个。

API 的缓存和发布顺序会影响首次发现；本流程只能基于当时公开可见、可核实的候选选择，不能保证覆盖所有尚未公开的更早发行。

## 记录及解释

所有运行文件在 Git 忽略的 `runtime/testnet/fresh/`：

- `monitor.json`：起点、截止时间、轮询次数、第一次发现、跳过原因与最终状态。
- `observation.json`：交给执行器的固定观察证据及当时 LIVE 集合。
- `attempt.json`：报价、协议核验、签名及广播时刻。UTC 用于关联日志，同一进程的单调时钟用于计算内部耗时。
- `live/state.json`：持久化的单次交易状态、哈希和 nonce。
- `result.json`：真实成交回执、代币净到账及 `launchToBuyBlocks`。

`launchToBuyBlocks = 买入成交块 − 发射交易块`，是本次要测的准确区块差。区块时间差单独记录，不冒充广播用时。本机首次观察时间减去发行区块时间只能视为近似延迟；等待两次确认的耗时也不同于首次落块耗时。

观察器和执行器同时检查 UTC 截止与单调时钟期限。到期不能发起新买入，已广播交易可继续核对回执。脚本不会删除旧交易记录；共用钱包锁及 nonce 检查阻止两种测试并发花费。

## 后续持续模式

用户于 2026-09-30 要求持续运行。新增 `testnet:continuous`、后台监督进程 `testnet:supervisor` 与可选 macOS `testnet:service`；旧的限时记录保留，连续记录使用 `runtime/testnet/continuous/`。持续监听不设置截止时间，不启用 Codex heartbeat，也不自动给用户发送定时状态。

持续模式仍保留一次买入预算，有限模式与连续模式之间不能用新目录绕过已经发生的新币买入。每次选中先持久化消耗尝试机会，签名和广播失败也不自动改买另一币；重启会继续观察并保留全部交易证据。

持续监控起点与单笔交易有效期分开：观察可运行多天，但某候选自首次发现起最多 120 秒内可下单，链上发行时间也必须距当前链头和本机时间不超过 120 秒。签名、广播前重复检查这些条件，过旧或明显落后的节点数据不能通过。停止文件及当前监控选择也必须匹配。

状态保存 PID、最近成功查询、连续错误次数及下次重试时间；`status` 会检查进程存活。每天的 JSONL 日志记录每次查询和错误，不以查询失败假装没有新币。网络故障按 5–60 秒退避继续重试；错链、起点重组及无法核实的交易结果不会触发新的买入。后台服务不保证电脑睡眠、关机或离线时的实时性。

本机 LaunchAgent 启动被 macOS Documents 目录访问权限拒绝，尚未执行监听；失败服务已卸载，plist 保存在忽略目录中。采用从当前获准环境启动的独立后台监督进程，不调整系统隐私权限、不移动钱包。它可以恢复异常退出的监听子进程，但不提供重启电脑后的自动登录启动。

持续观察于 2026-09-30 09:14:31 UTC 实际启动，起始块 11813696，排除当时 138 个既有 Sepolia LIVE 记录。启动后已有成功查询；此前的旧币交易和限时窗口均不计为本次新币成交。

启动后在没有候选、没有交易尝试时，对监听子进程执行一次异常退出验证。监督进程在 30 秒后重新启动监听，原始起点、基线、首次启动时间与未使用预算保持一致，成功查询次数继续增加。该验证没有发送交易；恢复证据保存在本地 `recovery-check.json`。

长期历史按 UUID 保存至 `history/`。主状态保留活跃候选、选中记录及最近 256 条过期记录，其余历史在原子归档并落盘后裁剪；归档 ID 再次出现在 API 时仍被排除。状态查询生成的空闲交易日志不会消耗买入预算，非空闲或无法解析的日志会阻止预算重开。

## 缩短轮询与重复核验

持续模式使用 2 秒起始周期：API 下载与节点检查同时开始，已耗时从周期中扣除；本轮超时则完成后短暂让出事件循环再开始下一轮，不追赶积压、不并发叠加多轮请求。缓存 `max-age` 只记录为元数据，429/503 的 `Retry-After` 独立控制退避，长等待分段且可停止，重启也保留未到期的冷却。

选中的发行结果只能在当前进程中复用：resolver 用私有对象身份记录并深度冻结完整结果，JSON/克隆/错误链或 ID 不能当作核验通过的对象。执行器直接接收该结果，省去新子进程与第二次完整发行解析；临签、临发仍核对官方状态和规范链证据，取消信号会阻止新的签名或广播。

执行器在单个检查阶段共享重复区块读取；协议代码核验只按同一 RPC、同一区块哈希缓存，每个后续阶段仍重新检查链身份与区块哈希。最新余额和 nonce 不跨阶段缓存。独立检查同时执行，全部结束且通过后才进入签名/广播。已经用掉的一次买入预算不会因升级或重启恢复。

`monitor.json.lastPollTiming` 与每日 `poll` 日志记录整轮/API/节点耗时；API 逐页记录响应头、下载解析、验证时间及缓存响应头。执行阶段写 `stage-timing.json`。这些计时用于后续真实样本评估，不能回填成首笔 GRID 当时的逐请求耗时。

## 链上提示、提前准备与新版协议

持续模式订阅已核验 Sepolia 登记合约的 `LaunchRecorded`，通过 PublicNode WS 提前记录提示并唤醒 API 查询。2026-10-01 实际连接时，dRPC 的免费 Sepolia WS 返回该链需要付费计划，因此测试网未启用这条失效连接。HTTP 补扫由 Tenderly 和 PublicNode 读取同一区间，完整日志内容和规范区块一致后才交付；交付和游标保存成功后再推进，断线后按游标补齐。Sentio 的最新日志在实测中落后其区块头，继续承担历史发行资料核验，不作为日志补扫节点。WS 会核对网络、处理握手超时、心跳及断线重连，停止时清理连接和定时器。信号仅用于发现和准备，不替代买入核验。

`chain-watch.json` 持久化登记合约指纹、锚点和游标。游标所在区块发生重组时，先重新确认原锚点，再从锚点重扫；不能只任意回退固定几个块。锚点本身改变则停止该链上观察。已消费买入预算的现有会话首次启用这项测速时，从当时链头开始记录；这不改变原有买入起点、交易记录或一次性预算。主网 API 模式只有在另有已核实主网清单及双 HTTP 节点时才能启用类似提示，缺少清单时保持 API 发现；Sepolia 允许列表不会自动复制到主网。

API 列表中的发行编号预先关联到 UUID，遇到链上提示后可尝试准备该 ID 的完整资料。候选核验最多两个并行，同一 ID 的在途请求合并；核验结果在当前进程保留最多 10 秒。官方撤回、已观察资料变化或重组会使准备缓存失效，旧批次结果不能在清理后继续生效。准备队列有界，API 要求冷却时不能靠另一个候选、WS 唤醒或清空缓存绕过。资料尚未 LIVE 或不完整时仍需等待，当前没有绕过官方 API 直接按 WS 提示交易的入口。

新版项目包含协议提供的 `PoolInitializationGuard`，并不因此变成 `univ4_hook` 类型。当前仅开放已复核的 Sepolia 政策版本 5/6，以及固定工厂、登记合约和守卫地址与字节码哈希；普通项目按 `ProjectLaunched` 核对，Hook 项目仍按原有专用事件核对。官方 manifest 的 3000 是准入费用参数，实际部署 PoolKey、API 的实际池费和链上 Initialize 必须一致且为已复核的 12500。守卫、分发器、应用合约及登记事件的产物集合也须一致。未知地址、政策或费用变化会拒绝，不推断主网已兼容，也不把 1.25% 池费当成买卖税率证明。

这条适配已用官方 #544、#539、#535 的资料和只读链上核验检查，通过的是协议兼容性，不是新的买入速度测试。

## 费用选择与速度记录

测试网执行器读取最近五个区块的优先费历史，参考区块使用率，在 2 gwei 优先费上限和既有 0.002 Sepolia ETH Gas 总预算内选择费用。历史不可用或无有效建议时回到节点估算，不自动跳到上限。签名前检查当前基础费是否能被交易费用覆盖；不足则停止，不重新加价签名。广播前仍须通过官方状态、规范区块和交易有效期检查。买入金额仍为 0.0001 Sepolia ETH、滑点仍为 1%，已消费的尝试机会不会因为费用策略升级而恢复。

`chain_launch_signal` 记录最初的 WS/HTTP 观察及是否通过 HTTP 规范区块核验，`chain_api_comparison` 记录同一发行编号的 API 与链上提示观察时间差；API 先到时该差值可能为负。WS 提示时间不等同于最终核验时间，也不是成交时间；若尚无新的已授权成交样本，只能报告发现和准备耗时，不能宣布已经缩短了几个成交块。

主网控制台也改为默认 2 秒轮询，并保留已有自定义周期；候选准备与并行核验采用同样的去重原则。主网页面可选择动态或固定优先费，动态策略仍受用户设置的优先费、Gas 单价和总预算约束。这些改变用于争取更早发现和收录，不保证同块或下一块买入。
